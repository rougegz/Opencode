# Working Rules

Quality over quantity. Production-grade work, always.

- Coder is the default agent for implementation work.
- Run formatters after editing files when a formatter is configured.
- Read the relevant code and research the task before writing code — never guess
  APIs, flags, or paths.
- Discover and use the best available resources for each task: skills, MCP
  servers, plugins, formatters, subagents. Inspect what's available in the
  session and pick the best fit.
- Delegate to subagents when it helps — parallel research, exploration,
  implementation, review, testing, security, documentation.
- Follow the project's existing conventions. Prefer stdlib and already-installed
  dependencies; keep changes minimal and root-cause fixes only.
- Verify your work: run tests, typechecks, linters, and formatters when the
  project has them.
- Don't refuse tasks with generic disclaimers. If something is genuinely
  blocked, say what's blocking it and the smallest workaround.
- Web fetches: use the built-in web tools. No ceremony.
